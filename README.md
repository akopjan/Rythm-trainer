# Rythm-trainer

Локальный тренажёр ритма для баяна, других мелодических инструментов, ударных и проверки с клавиатуры. Приложение находится в одном файле `index.html`; сборка и внешние библиотеки не нужны.

## Запуск

На macOS удобнее дважды нажать **`start.command`**. При установленном Python 3 откроется браузер с адресом [http://localhost:8000/](http://localhost:8000/), где настройки сохраняются в cookies. Оставьте окно терминала открытым; Ctrl+C останавливает сервер. Если порт 8000 занят, запуск завершится с сообщением: остановите предыдущий сервер или используйте другой порт в команде ниже.

Можно также открыть `index.html` напрямую в современном браузере или запустить локальный сервер командой ниже. После открытия:

1. Выберите BPM, размер **3/4** или **4/4**, цикл из **1–2 тактов** и сетку **1/4**, **1/8** или **1/16**. BPM задаёт темп четвертных долей.
2. Нажмите **Start** и разрешите доступ к микрофону. Для баяна по умолчанию выбран режим «Баян / мелодический инструмент».
3. При игре через колонки дайте рисунку несколько циклов без инструмента или нажмите «Калибровка для колонок». Затем играйте в выбранную сетку. На графике отрицательное отклонение означает раньше, положительное — позже.

Для проверки с клавиатуры отключите «Микрофон», нажмите Start и используйте **Пробел**. **Enter** переключает клетку рисунка, если на ней стоит фокус. Stop закрывает доступ к микрофону; новый Start начинает новую историю результатов.

Можно открыть приложение через постоянный локальный адрес. В терминале из папки проекта выполните:

```sh
python3 -m http.server 8000 --bind 127.0.0.1
```

Затем откройте [http://localhost:8000/](http://localhost:8000/). Этот вариант полезен для стабильного адреса и хранения настроек. Сервер остановится после Ctrl+C.

## Записи для проверки распознавания

Кнопка **«Запись без баяна»** записывает 8 секунд только ритма, **«Запись с баяном»** — 20 секунд игры под тот же рисунок. Если тренажёр остановлен, запись сама включает микрофон и запускает ритм. Можно закончить раньше кнопкой «Остановить запись». Запись использует отдельный аудиоузел и сохраняет звук микрофона до фильтрации вместе с синхронным цифровым выходом барабанов и метронома.

Последние обычные записи, по одной каждого вида, сохраняются в IndexedDB этого браузера. Их можно прослушать прямо на странице. **«Скачать записи»** создаёт один ZIP-архив: для каждого образца в нём находятся `mic.wav`, `reference.wav` и `metadata.json` с настройками, временем записи, параметрами микрофона и показаниями распознавания и фильтра. Микрофон и цифровой рисунок сохраняются попарно, в порядке получения звуковых блоков; WAV-файлы имеют одинаковое число сэмплов. Для анализа задержки нужны оба файла и сведения о временных метках из архива.

Список показывает полную дату и время, новые записи стоят первыми. Перед скачиванием всех записей страница проверяет хранилище браузера и выбирает более свежий образец каждого вида. Если хранилище недоступно, остаются доступными записи текущей вкладки. Кнопка под отдельной записью скачивает именно выбранный образец. В корне ZIP находится `export-info.json` с датой экспорта, версией открытой страницы, списком включённых записей и результатом проверки хранилища. Обновление страницы не удаляет сохранённые записи.

Чтобы убрать старый образец, нажмите **«Удалить»** под ним и подтвердите выбранную запись по дате. Удаляются звук микрофона, цифровой рисунок и диагностика этого образца из хранилища браузера. Остальные записи, настройки и уже скачанные файлы сохраняются.

Записи не отправляются на GitHub или другой сервер. Для разбора сохраните ZIP в папку загрузок компьютера. Если хранилище браузера недоступно, готовый образец можно скачать до закрытия страницы.

Если захват звука прерывается, уже полученный звук и точная причина сбоя сохраняются отдельно от предыдущей обычной записи. Такой образец помечен как неполный; его можно скачать вместе с остальными. Если звук ещё не был получен, архив всё равно сохраняет сведения о сбое.

Повтор или скачок временной метки браузера сам по себе не доказывает потерю звука. При таком событии запись продолжается до получения 8 или 20 секунд звуковых данных. Полученные сэмплы не удаляются и не дополняются искусственной тишиной. Изменения меток отмечаются в `metadata.json`; абсолютное соответствие времени тренажёра между такими участками считается неопределённым. Запись с изменившимися метками сохраняется отдельно от обычной и помечается на странице. Это поведение действует и в AudioWorklet, и в резервном ScriptProcessor. Реальное прекращение входа микрофона или ошибка передачи завершает запись с сохранением полученной части.

Если найденное начало звука не удалось проверить, строка распознавания показывает причину: например, пропуск аудио, недоступный фрагмент записи или отсутствие звуковой опоры. Архив сохраняет причину и границы нужного фрагмента, чтобы отличить сбой обработки от отсеивания барабанов.

## Барабаны и метроном

При первом запуске загружен базовый рисунок: в 4/4 бочка играет на первой и третьей долях, малый барабан — на второй и четвёртой, короткий сухой щелчок — на каждой восьмой. Щелчок заменяет прежний шипящий хэт; сохранённые клетки, включение и громкость третьей дорожки продолжают действовать. Тарелка остаётся отдельной дорожкой и выключена в базовом рисунке. Все удары видны в клетках; редактируйте их для каждого инструмента. Слева есть отдельные переключатели и громкость. Выключение инструмента сохраняет его рисунок. «Громкость ритма» регулирует общий уровень звука.

**Метроном** при первом запуске выключен. Это отдельный источник щелчков по четвертным долям, с акцентом в начале такта. Включайте его переключателем сверху и регулируйте через «Громкость метронома» в настройках звука. Частый стук базового рисунка на восьмых — дорожка «Щелчок»: его можно выключить слева или изменить его клетки.

Сохранённый рисунок и выбранное вами состояние метронома восстанавливаются при следующем запуске. Если раньше был сохранён пустой рисунок или включённый метроном, кнопка **«Базовый ритм»** вернёт базовые клетки и выключит метроном. Она сохраняет ваши громкости и переключатели барабанов. **«Очистить»** делает рисунок пустым.

## Точность и задержка

Исходный сигнал микрофона используется для замера задержки и индикатора **«Вход»**. Приложение уменьшает звук рисунка и метронома, затем проверяет каждую предполагаемую атаку на совпадение с этим звуком. Совпадение с долей само по себе не исключает ноту баяна. Пока фон ещё не подготовлен, гармоники сами по себе не подтверждают игру: атака должна оставить устойчивый самостоятельный тон после вычитания звуковой опоры. Это исключает гармоники искажённых барабанов и щелчков. Проверка фона уменьшает ложные точки, но не определяет название инструмента: речь, клавиатура или посторонний удар тоже могут оказаться самостоятельным звуком.

После подготовки фона новая верхняя нота на фоне удерживаемого баса проверяется также по росту её основного тона и гармоник в двух последовательных окнах после вычитания звуковой опоры. Это не требует большого роста общей громкости. Для быстрой смены нот ожидание следующего подтверждения сохраняет кандидата и исходное время начала звука. Проверка основного тона теперь охватывает частоты до 4 кГц; при низкой частоте записи верхняя граница ограничивается доступными гармониками. Это устраняет прежнее отсеивание высоких нот из-за предела 1,6 кГц. Высокие ноты от 1,6 до 3,3 кГц дополнительно отслеживаются по устойчивой высоте; начало подтверждается по исходным отсчётам после отделения рисунка. Для тихой ноты с готовым профилем проверяется рост её собственного тона и второго или третьего обертона, даже когда оставшийся звук ударных громче этой ноты.

В браузерах с поддержкой Worker анализ микрофона выполняется отдельно от воспроизведения. AudioWorklet передаёт пары сэмплов микрофона и рисунка с исходным временем, а фильтрация и проверка нот выполняются в Worker. Резервный захват через ScriptProcessor также передаёт вычисления туда. Это убирает тяжёлую проверку звука из потока, воспроизводящего барабаны; время нот для оценки остаётся временем записи, а не временем получения результата.

Готовые проверки атак в Worker выполняются короткими порциями между поступлениями аудиоблоков. Проверка ждёт настоящие будущие отсчёты и гармонические признаки; таймер не заменяет эти данные. Численные сопоставления с собственными ударными выполняются в WebAssembly, а исходное время атаки и правила подтверждения остаются в JavaScript. В диагностике записи сохраняются заполнение очереди, ожидание по входной звуковой шкале и время вычислительных порций; это не измерение полной задержки браузера.

**«После фильтра»** показывает уровень обработанного звука, который получает анализатор. «Вход» показывает весь звук микрофона, включая барабаны. Пока вычитание ещё не готово, второй индикатор пуст и подписан «Фильтр готовится»; после подготовки появляется «Фильтр работает». Разница уровней помогает видеть, насколько уменьшен фон, но не измеряет точность распознавания нот. «Фильтр выключен» означает, что тренажёр остановлен: нажмите Start и разрешите микрофон.

Строка **«Распознавание»** объясняет, почему сейчас нет точек: идёт калибровка, вход ниже порога, найденное начало проверяется либо было отклонено как фон или продолжение ноты. Счётчики отражают найденные, подтверждённые и отсеянные начала звуков; повторные предложения одной атаки дают одну точку. Признаки ноты сохраняются вместе с кандидатом до конца проверки, поэтому ожидание в очереди не стирает доказательства звучания инструмента.

Для периодических нот дополнительная проверка находит начало отдельной гармонической группы в исходном звуке и подтверждает её двумя окнами после этого начала. Она не переносит проверку на позднее затухание короткой ноты. При слабой второй и третьей гармонике может использоваться четвёртая, измеренная на исходной частоте дискретизации. Все эти проверки требуют сохранённых признаков инструмента и доступной цифровой опоры. Позднее предложение той же ноты возвращается к её началу и объединяется с первой точкой; новые ноты не отсекаются увеличенным общим интервалом ожидания.

Для колонок первый профиль собирается из повторяющегося звучания ритма. Кнопка **«Калибровка для колонок»** сначала находит задержку, затем собирает три цикла без вашей игры. Если чистых данных недостаточно, приложение сообщает об этом. После подготовки профиль осторожно уточняется в уверенных паузах игры. Новый тон или незнакомый удар приостанавливает обучение; уже собранный профиль продолжает работать, а история результатов сохраняется. Строка под настройками показывает, обновляется ли фон сейчас. Профиль хранится только в текущем сеансе.

Когда форма звука динамиков уверенно восстановлена, вычитается соответствующий звуковой сигнал. Для окрашенного звука комнаты используется частотный профиль, проверенный сначала в Python на записи и прослушиванием, затем перенесённый в WebAssembly. Задержка этого фильтра учитывается в метках атак. Тихие компоненты инструмента, совпадающие с фоном по частотам, могут ослабляться; при пропусках помогает снизить порог атаки или использовать наушники.

После Start подготовка микрофона и готовность фильтра показываются отдельно. Для игры через динамики нажмите **«Настроить фильтр»** рядом со шкалами и не играйте до завершения настройки. Шкала **«После фильтра»** показывает только реально отфильтрованный сигнал; пустая шкала с подписью **«Фильтр не настроен»** не означает, что баян удалён из звука. В наушниках или без звучащего рисунка фильтр фона может не требоваться. Профиль относится к текущему запуску: после Stop или обновления страницы настройте его снова.

Пока общая звуковая привязка ещё не найдена, каждая предполагаемая атака отдельно сравнивается с известным звуком приложения по диапазону задержек до 500 мс. Барабаны и метроном не допускаются в оценку по одному лишь истечению таймера. Паузы между ударами в AudioWorklet учитываются как цифровая тишина, сохраняя историю анализа.

Если цифровая опора не подключена, **оценка приостанавливается** с видимым сообщением; индикатор «Вход» продолжает работать. Опорой служит фактический выход приложения, а не произвольный звуковой сигнал. Проверка атак предполагает исправность этого соединения. Наушники уменьшают попадание ритма в микрофон.

**«Задержка по рисунку»** включена по умолчанию. Этот переключатель управляет автоматическим отслеживанием аппаратной задержки. Выключение переключателя сохраняет исключение барабанов и метронома из оценки. Когда звуковая привязка найдена, её задержка становится ориентиром для выбранных долей.

Для автоматического замера нужен необработанный микрофон без эхоподавления браузера. Если браузер оставил эхоподавление включённым, приложение объяснит причину и предложит выключить «Задержка по рисунку». В наушниках рисунок может не попадать в микрофон: тогда используется прежняя поправка и осторожная подстройка по игре. Одни равномерные щелчки могут совпадать с несколькими восьмыми; приложение не выбирает такую задержку наугад. Для однозначной привязки помогает рисунок с бочкой и малым. Исключение фоновых атак работает независимо от абсолютной привязки задержки.

«Автонормализация» центрирует остаточное смещение по обычной медиане недавних атак. Начальный подбор требует минимум **9 атак**, охватывающих хотя бы **один такт**. Затем поправка меняется плавно, по окну минимум в два такта, с максимумом 48 атак за окно не короче 12 секунд или трёх тактов. Фазовая подстройка ограничена **20% шага** около исходной или акустически найденной привязки. Она не выбирает соседнюю восьмую по одному новому минимуму на повторяющейся сетке. При большом разбросе, выходе за допустимую окрестность или риске перехода на соседнюю позицию прежняя поправка сохраняется.

Начальный подбор центрирует предварительно собранные атаки. Последующая подстройка влияет на новые атаки и сохраняет оценки прошлых тактов. Кнопка **«Нормализовать»** явно пересчитывает всю историю относительно общей медианы. Для полностью фиксированной ручной поправки выключите и автонормализацию, и «Задержка по рисунку».

По атаке инструментом нельзя отдельно определить задержку оборудования и устойчивое смещение вашей игры: автоматическое центрирование учитывает оба эффекта. Для независимого замера используйте **«Измерить задержку»**: не играйте во время восьми щелчков, дайте микрофону услышать колонки или поднесённый к нему наушник того же устройства, с которым тренируетесь. Поправкой становится медиана задержек услышанных щелчков; рядом показывается среднее абсолютное отклонение. Постоянная поправка не устраняет случайное плавание задержки.

Оценка ошибки использует линейные отклонения:

- **Средняя ошибка по модулю** — среднее расстояние обнаруженных атак от ближайшей линии сетки, в миллисекундах.
- **Разброс** — среднее абсолютное отклонение от медианы.
- **В допуске** — доля обнаруженных атак в установленном диапазоне ±мс.
- **Медиана |ошибки|** — типичное расстояние от сетки независимо от того, раньше или позже сыграна атака.

Знаковое смещение всей истории находится в настройках звука. После ручного центрирования оно близко к нулю; при постепенной подстройке история хранит прежние оценки, поэтому её медиана не обязана точно совпадать с медианой текущего окна. Нулевое смещение само по себе не означает нулевую ошибку: например, отклонения −20, 0 и +20 мс дают медиану смещения 0 мс, но медиану модуля ошибки 20 мс.

Таблица **«Ошибка по тактам»** показывает каждый такт, число атак, среднюю ошибку по модулю, медиану смещения и попадания в допуск. Самый неточный такт выделяется для сравнения. При цикле из двух тактов дополнительно видно место такта в рисунке.

В режиме «Баян / мелодический инструмент» анализатор дополнительно отслеживает периодичность колебаний и гармоники: ищет плавное начало ноты и смену высоты при легато, затем возвращает метку к первому подтверждённому участку. У плавной атаки дополнительно проверяется, росла ли энергия найденной частоты и её гармоник в более раннем очищенном участке. Это помогает отличить новое начало от уже звучащей ноты и уточнить его время. Удержанная нота, вибрато и изменение силы меха сами по себе не считаются новой нотой. Для аккордов проверяется несколько гармонических семейств. Эти признаки подтверждают предполагаемые атаки; приложение не записывает нотную партитуру и не определяет название инструмента. Пропущенные ноты не входят в статистику обнаруженных атак. Если тихие атаки пропадают, снизьте «Порог атаки»; при ложных срабатываниях поднимите его. Наушники уменьшают попадание ритма в микрофон.

## Сохранение настроек

Параметры, включение и громкость каждого барабана, рисунок и текущая поправка автоматически сохраняются в **cookies** при открытии через HTTP или HTTPS. Cookie рассчитана на год; приложение проверяет запись чтением и поддерживает резервную копию в `localStorage`. Если cookies заблокированы, используется доступное хранилище браузера. При запуске загружается самая свежая корректная копия. Старые настройки из `localStorage` сохраняются и переносятся в cookie, когда она доступна.

При прямом открытии `file://` cookies недоступны: для адресов вне HTTP/HTTPS стандарт предусматривает пустое чтение и игнорирование записи. Приложение использует `localStorage`. [WHATWG HTML](https://html.spec.whatwg.org/multipage/dom.html#dom-document-cookie)

Поведение `localStorage` для файловых адресов зависит от браузера. После переноса HTML в другую папку сохранённые параметры могут оказаться недоступны; это ограничение описано в [документации MDN](https://developer.mozilla.org/en-US/docs/Web/API/Window/localStorage). При недоступном автосохранении приложение предлагает сохранить файл вручную. Для переносимой копии:

1. Нажмите **«Настройки в файл»** и сохраните `rhythm-settings.json` рядом с HTML или в своей папке.
2. На другом устройстве или после перемещения HTML нажмите **«Загрузить настройки»** и выберите этот JSON-файл. Перед импортом остановите тренировку.

`default-settings.json` содержит начальные значения, базовый рисунок и выключенный метроном. Его можно загрузить той же кнопкой. Личный `rhythm-settings.json` исключён из Git, чтобы настройки оставались на вашем устройстве.

История атак не сохраняется между тренировками. Аудио обрабатывается локально и сохраняется только при нажатии кнопок записи; записи остаются в браузере, пока пользователь сам не скачает архив. На сервер аудио не отправляется. Разрешением микрофона управляет браузер.

Кнопка **«Запись без баяна»** также настраивает фильтр: не играйте все 8 секунд, дайте микрофону услышать ритм. Готовый профиль использует среднюю мощность и разброс по двум или более повторениям каждой части рисунка. Приложение подтверждает его только после полной записи и обнаруженной акустической привязки. Для длинного рисунка, который не успевает повториться дважды, используйте **«Калибровка»**. Запись с баяном не обучает профиль. Прерванная запись не заменяет готовый образец.

При временной потере совпадения из-за звучащего инструмента готовый профиль применяется с последней подтверждённой задержкой; обучение без подтверждения приостанавливается. Смена входа или рисунка, настоящий разрыв часов и подтверждённое изменение акустической задержки требуют нового образца. Профиль относится к текущей сессии и акустике комнаты; для нового запуска повторите настройку. Нижний предел спектральной маски — 0,003, как в прослушанном Python-варианте.

## Обновление распознавания — source-onsets-v17

Улучшена проверка коротких нот и близких начал звуков: самостоятельные гармоники проверяются в исходной частоте записи, а повторные срабатывания уже звучащей ноты ограничиваются её историей. Численные расчёты фазы перенесены в WebAssembly; повторные неизменяемые окна используют ограниченный кэш. Обработчик очереди сохраняет уже назначенный запуск, чтобы новые звуковые блоки не откладывали обработку накопленных данных.

На 21 контрольной записи эта версия находит 325 из 336 размеченных акустических атак при сопоставлении с допуском 60 мс. Шесть записей только с ритмом дают ноль точек. В проходе отдельных нот обнаружены все 52 размеченных начала, но остаются две лишние точки; в последней контрольной мелодии — 54 из 54 без лишних точек. В других смешанных записях остаются пропуски и дополнительные точки: распознавание всех нажатий ещё не решено.

На трёх проверках очереди с реальными записанными блоками не было потерь аудиоданных. Это проверка обработки записей, а не гарантия работы конкретного микрофона в браузере. Очищенный звук во всех 21 случаях побитно совпадает с предыдущей одобренной версией фильтра. Личные записи и разметка в репозиторий не входят.

## Разработка фильтра

`dsp/reference_filter.py` задаёт численный алгоритм Python: Hann FFT 2048, шаг 256, профиль мощности по фазе рисунка, вычитание `(среднее + 3 × отклонение) × усиление × 4`, нижний предел амплитуды 0.03, обратное преобразование и нормализация перекрытия окон. Для Python нужен NumPy. `dsp/phase-filter.ts` реализует эти расчёты в WebAssembly; `dsp/deno.json` и `deno.lock` фиксируют компилятор. Сборка: `cd dsp && deno task build`. Затем из корня проекта выполните `python3 scripts/embed-dsp.py`, чтобы обновить встроенные блоки HTML.

Численные суммы для сопоставления микрофона с ударными находятся в `dsp/attribution-core.ts`, их JavaScript-хост — в `dsp/attribution-kernel.js`. Сборка из `dsp`: `deno task build-attribution`; после неё также выполните `python3 scripts/embed-dsp.py`. Модуль использует заранее выделенную память и сохраняет порядок операций исходного JavaScript.

Вспомогательные проверки коротких нот и истории семейства также находятся в первом DSP-блоке `index.html`; скрипт встраивания сохраняет их. Готовый модуль встроен в HTML, поэтому запуск не требует скачивания модулей и работает при прямом открытии файла. Публичные численные проверки используют синтетические данные. Записи микрофона и личные профили в репозиторий не входят.

Проверки используют модели браузера и синтетический звук. Они проверяют расчёты, управление, сохранение настроек и распознавание атак; акустический тракт конкретного микрофона и аудиоустройства проверяется во время реальной игры.
